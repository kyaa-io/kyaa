# 검색 변경 통지와 유입 후 전환

## 공개 페이지 발견

`server/seo/sitemap-content.ts`가 사이트맵과 변경 통지에 쓰는 공개 콘텐츠를 함께 읽는다. 실제로 공개된 크리에이터, LIVE, 선물 목록·상세와 해당 페이지가 제공하는 언어만 포함한다. 선물 목록에 보이는 공개 예고는 목록 내용에는 반영하지만 아직 공개되지 않은 상세 주소는 추가하지 않는다. 일부 조회가 실패하거나 페이지 수가 도중에 바뀌면 전체 작업을 실패시켜 잘못된 삭제 통지를 막는다.

## 변경 통지

운영 Vercel cron이 5분마다 `/api/internal/seo/indexnow`를 호출한다. 기존 `CRON_SECRET` 인증을 사용하고 운영 환경에서만 동작한다. 전체 공개 콘텐츠의 안정적인 내용 지문을 이전에 접수된 지문과 비교해 추가·수정·제외된 주소만 공식 IndexNow endpoint로 전달한다. 사용자 상태·팬 수·현재 시각은 지문에 넣지 않는다. 정적 문구는 배포 커밋이 바뀌면 다시 통지하며 공개 목록도 게시 데이터 변경을 반영한다.

`search_indexnow_state`는 서비스 역할만 읽고 수정한다. 겹친 실행은 5분 lease와 토큰으로 제한한다. 모든 묶음의 응답이 200 또는 202일 때만 지문을 갱신하므로 실패한 통지는 다음 주기에 다시 시도한다. 202는 키 검증 대기를 뜻하며 검색 반영 완료가 아니다. 네트워크 응답이 유실되면 같은 주소가 재통지될 수 있다. 외부 전송에는 정규 공개 주소와 공개 소유 확인 키만 사용한다.

앱보다 먼저 `20261018082701_search_indexnow_state.sql`, `20261018082738_acquisition_conversion_analytics.sql`을 적용한다. 소유 확인 파일은 앱의 루트 정적 파일로 배포된다. 별도 유료 서비스나 추가 환경 변수는 필요하지 않다.

## 자동 점검

`Search health` GitHub Actions가 운영 배포 성공 후, 매일 한국 시간 07:43, 수동 실행 시 동작한다. 신뢰한 저장소와 Vercel 배포 이벤트만 허용하고 현재 main의 코드를 실행한다. robots·사이트맵, 홈/크리에이터/LIVE/선물 목록·상세의 KO/EN, JA→EN 대표 URL, 초기 head 메타, 실제 이미지 응답과 외부 표시 정책, 없는 페이지의 noindex, 익명 API 접근 거부를 검사한다. 어느 공개 종류·언어가 전부 사라져도 검토가 필요하도록 실패시킨다.

실패는 Actions 상태에서 확인하며 JSON 증거를 30일 보존한다. 별도의 메신저 알림을 보내지 않는다. 점검은 일부 대표 페이지의 응답 검사이며 모든 URL의 순위나 색인을 보장하지 않는다.

검증 명령: `node --test scripts/search-health.test.mjs`, `node scripts/search-health.mjs`. 출력 위치는 `SEARCH_HEALTH_OUTPUT`으로 지정한다. 검사 대상 호스트는 운영 kyaa로 고정되어 있다.

## 유입 후 전환

관리자 `/admin/traffic`에서 같은 7·30·90일 조건으로 조회한다. 기존 탭 단위 첫 유입 기록을 사용하며 선물 목록·상세도 `benefit` 첫 화면으로 분류한다. 선택 기간 안의 첫 식별 유입 이후 발생한 가입·프로필·예약·응모의 확정 기록을 각각 회원당 한 번 집계한다. 출석이나 팬 인증을 먼저 해야 집계되는 순차 퍼널이 아니다.

신규 회원 수와 전체 생애 최초 유입을 뜻하지 않는다. 익명 방문 기록을 회원과 결합하지 않으며, 개인 식별자·원본 주소·검색어는 반환하지 않는다. 1~4명인 수치와 이를 역산할 수 있는 합계는 숨긴다. 검색어별 노출·클릭은 Search Console에서, 공개 페이지·유입 도메인별 방문은 기존 방문 통계에서 확인한다. 보고서는 유입과 실제 참여를 비교할 수 있지만 특정 검색어를 특정 회원에게 연결하지 않는다.

관련 검증: `supabase/tests/search_indexnow_state.sql`, `supabase/tests/acquisition_conversion_analytics.sql`, `server/seo/*test.ts`, acquisition 관련 웹 테스트. 기존 안내·FAQ는 이미 공개 본문과 구조화 데이터가 일치하므로 이번 작업에서 새 질문을 임의로 만들지 않았다.
