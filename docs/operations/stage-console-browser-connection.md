# Mac 무대 앱과 운영 브라우저 연결

2026-10-22 운영 확인에서 관리자 화면은 정상 로드됐지만 `connect-src`에 로컬 소켓이 없어 연결 버튼을 눌러도 Mac 앱과 연결되지 않았다. Vite에서 실행한 소켓 통합 검사에는 Next 응답 보안 헤더가 없어 이 차이를 발견하지 못했다.

## 연결 범위

- 정확한 `/admin/wave-stage` 문서만 `ws://127.0.0.1:*/source` 연결을 허용한다. Mac 앱이 매 실행마다 비어 있는 포트를 선택하므로 포트만 가변이다.
- 다른 문서의 CSP와 `/source` 외 경로·다른 호스트 제한은 유지한다. 브라우저는 64자리 소스 토큰이 포함된 정해진 형식만 받고, Mac 서버는 loopback 주소·소스 토큰·관리자 웹의 Origin을 모두 검사한다.
- 브라우저의 로컬 네트워크 접근 권한은 CSP와 별개다. Chrome 147부터 로컬 WebSocket에도 이 권한이 적용된다. 연결 버튼을 누를 때 해당 사이트의 권한 요청이 나타나면 Mac 앱 연결을 위해 허용한다. 보안 기능을 끄거나 인증서 경고를 우회하는 방식으로 해결하지 않는다.

## 관련 변경 확인

연결 프로토콜·출처·보안 헤더를 바꿀 때는 다음 범위를 확인한다.

1. `security-headers.test.ts`로 실제 Next 설정에서 무대 화면의 단일 CSP와 다른 경로의 기존 정책을 대조한다.
2. 실제 HTTPS 브라우저에서 로컬 `/source`만 연결되고 다른 경로·호스트는 차단되는지 확인한다. 격리된 테스트의 권한 허용 결과와 실제 사용자 브라우저의 권한 상태를 구분한다.
3. 운영 반영 뒤 기본 보안 설정의 사용자 브라우저에서 **무대 콘솔 연결됨**과 Mac의 **데이터 소스 연결됨**을 모두 확인한다. 상태 확인을 위해 실제 회원에게 도장을 발급하거나 운영 추첨을 실행할 필요는 없다.

Chrome의 권한 적용 근거: [Local Network Access restrictions for WebSockets](https://developer.chrome.com/release-notes/147#local-network-access-restrictions-for-websockets).
