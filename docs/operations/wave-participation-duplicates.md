# Wave 동명 참여 확인

새 계정의 참여 이름이 기존 참여 이름과 같으면 `PARTICIPATION_REVIEW_REQUIRED`(HTTP 409)로 보류한다. 이름은 NFKC 정규화 후 공백 제거·소문자 변환한 값의 행사 전용 HMAC으로 비교한다. 저장·표시하는 원문 이름은 바꾸지 않는다. 다른 계정에 같은 이름이 있다는 상세 정보는 API에 반환하지 않는다. 기존 참여 영수증과 동일 요청 재시도는 유지한다.

신규 NULL 지문 삽입은 DB 제약으로도 차단한다. 마이그레이션 도중 실행 중이던 구버전 요청은 실패할 수 있으므로 갱신 후 다시 시도한다. 기존 참여자의 `name_fingerprint`가 하나라도 비어 있으면 모든 신규 참여를 보류한다. 서버의 기존 암호화 키로 이름을 복호화하고 `participationNameFingerprint(name, key)`를 적용하는 비공개 백필을 먼저 완료해야 한다. 키를 바꾸면 기존 암호화 이름과 지문의 호환성이 깨지므로 임의로 회전하지 않는다. 5개 인자만 보내는 구버전 서버는 새 참여를 등록할 수 없다. 백필 뒤 `ALTER TABLE public.kyaa_wave_participants VALIDATE CONSTRAINT kyaa_wave_participants_name_fingerprint_required`로 기존 행까지 검증한다. 배포·백필 순서는 해당 배포의 검증된 비공개 도구를 따른다.

## 실제 동명이인 예외

운영자가 서로 다른 실제 사람임을 확인했을 때만, 해당 계정 UUID와 해당 이름 지문에 1회 예외를 승인한다. 별도 대기열·관리 화면은 없다. 잘못된 코드나 다른 이름의 요청은 예외를 소모하지 않으며, 성공한 참여 삽입과 함께 소모된다. 동일 예외를 다시 승인할 수 없다. 계정 비활성화·삭제 시 예외의 개인 데이터도 제거한다.

1. 본인 확인 근거로 대상 `app_users.id`를 정확히 확정한다. 이메일은 고유하지 않을 수 있으므로 이메일 검색에 `LIMIT 1`을 붙여 대상을 결정하지 않는다. 조회 결과가 여러 개면 운영자가 올바른 UUID를 확정한다.
2. 기존 운영자 본인의 `app_users.id`와 연결된 활성 `admin_allowlist.id`를 확정한다. 읽기 전용 viewer는 승인할 수 없다. 대상 이름 원문과 기존 참여 이름을 권한 있는 환경에서 확인하고, 서버의 키와 같은 함수로 이름 지문을 계산한다. 암호화 키·원문 이름·이메일·지문을 공개 로그나 이슈에 붙이지 않는다.
3. 서버 전용 서비스 자격증명으로 다음 RPC를 호출한다. 서비스 자격증명은 브라우저·클라이언트에 넣지 않는다. 아래 값은 실제 UUID·확인한 지문·새 추적 UUID로 치환하는 예시이며 운영 실행 기록이 아니다.

```sql
select public.grant_kyaa_wave_participation_name_exception(
 p_actor_app_user_id := '11111111-1111-4111-8111-111111111111'::uuid,
 p_actor_admin_allowlist_id := '22222222-2222-4222-8222-222222222222'::uuid,
 p_correlation_id := '33333333-3333-4333-8333-333333333333'::uuid,
 p_app_user_id := '44444444-4444-4444-8444-444444444444'::uuid,
 p_name_fingerprint := repeat('a',64)
);
-- 성공: {"approved": true}
```

승인은 활성 대상 계정이고 같은 지문의 기존 참여가 있을 때만 가능하다. 기존 참여자인 대상, 잘못된 지문, 재승인은 거절한다. 승인 후 대상자가 같은 이름과 올바른 행사 코드로 다시 참여한다. 백필 누락에 따른 전체 보류는 예외로 우회할 수 없다. 예외 승인 이력은 운영자 식별자와 추적 UUID로 감사 로그에 남으며 원문·이메일·지문은 감사 로그에 넣지 않는다.

## 로컬 검증

깨끗한 폐기용 DB에 전체 마이그레이션을 적용한 뒤 `supabase/tests/kyaa_wave_participation.sql`을 `psql -X -v ON_ERROR_STOP=1 -f`로 실행한다. 같은 폐기용 DB 연결 환경에서 기존 `kyaa_wave_participation_concurrency.sh`를 실행한다. 두 기존 진입점이 동명 SQL·경합 테스트도 함께 실행한다. 동명 동시 신규 요청은 1명만 등록되어야 하고, 승인/비활성화 경합 뒤에는 비활성 계정의 예외가 없어야 한다. 운영 DB에서는 이 테스트를 실행하지 않는다.
