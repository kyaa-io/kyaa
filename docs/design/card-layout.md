# 반복 카드의 높이와 정렬

2026-10-19 패스포트 높이 차이 제보에서 확인한 계약이다. `AGENTS.md` → `DESIGN.md` → 이 문서 순서로 적용한다. UI 작업 시작 시 `ui-skills-root`에서 주제·스택·구체성 순서로 필요한 스킬을 고른다. 기존 Kyaa 브랜드와 승인된 이미지 구도를 우선한다.

## 구현 기준

- 한 행에 놓이는 같은 역할의 카드는 외곽 하단, 비교할 수치, 마지막 행동 영역을 함께 정렬한다. 카드 외곽만 늘리고 버튼은 본문 바로 뒤에 두면 해결되지 않는다.
- 짧은 이름과 긴 이름, 줄바꿈된 등급, 발급 완료·대기·실패, 실제 버튼과 준비 상태가 섞여도 적용한다. 선택 정보가 없다고 의미 없는 문구를 만들지 않는다.
- 높이는 내용으로 결정한다. 전역 고정 높이, 이름 생략, 작은 글씨, 숨긴 넘침으로 차이를 덮지 않는다. 여백은 같은 행에서 공유하고 다음 행이나 모바일 단일 열에 불필요하게 전파하지 않는다.
- 패스포트는 공통 목록 소유자 `features/passport/ui/passport-screens.module.css`에서 라벨·본문·선택 상태·행동의 네 트랙을 CSS subgrid로 공유한다. 본문의 수치는 아래에 정렬한다. 단일 카드의 최대 폭 380px와 44px 이상의 행동 영역을 보존한다.
- 추첨은 기존 flex 본문과 자동 하단 여백을 유지한다. 준비 상태도 행동과 같은 최소 46px 영역을 갖는다. 디렉터리의 기존 stretch/flex 정렬은 재사용한다. LIVE의 단일 열 항목이나 역할이 다른 MY 패널에 동일 높이를 강제하지 않는다.

## 검증과 완료 기준

`node apps/web/e2e/community-stamps-local/passport-run.mjs`

실제 제품 컴포넌트·CSS와 로컬 합성 API 응답을 사용한다. 운영 인증·회원 데이터는 사용하지 않는다. URL의 `view=passports&data=demo|mixed|one|empty|error`, `auth=off`와 `view=raffle-layout`으로 재현한다.

- `APP_LOCALES`의 모든 언어를 390/1440px, KO/JA/VI/TH를 360/768px에서도 검사한다. 언어 추가 시 이 범위를 자동으로 확장한다.
- 긴 행사명·복합 이름, 큰 점수, 완료·대기·실패를 섞은 패스포트와 긴 제목·설명·행동·준비 상태가 섞인 추첨을 검증한다.
- 같은 행의 카드 높이·비교 수치·행동 기준선 오차는 1 CSS px 이하다. 가로 넘침·런타임 오류가 없어야 하고, 키보드 초점과 터치 영역을 유지한다. 패스포트의 빈 상태·단일 항목·인증·오류 상태와 WCAG A/AA도 검사한다.
- Fan design system CI에서 브라우저 검사를 실행하고 실패 시 병합 전에 고친다. 스크린샷과 측정 결과를 CI 산출물로 보존한다. 새 카드 역할은 기존 검사 패턴을 확장하되 역할이 다른 화면을 무조건 합치지 않는다.
- 자동 통과만으로 미적 검수를 대체하지 않는다. 390/1440px 실제 캡처에서 정보 밀도, 이름과 등급의 간격, 이미지 프레임, 불필요한 빈 공간, 버튼·수치 정렬을 직접 확인한다. 이미지 표시 변경 시 `image-framing.md`도 적용한다.
- 운영 UI 변경에는 새 배포 안내와 직접 확인한 공개 가능한 캡처를 추가한다. 합성 데이터 캡처라는 사실을 안내에 밝힌다. 사이트 전체나 미확인 상태가 안전하다고 확대해 보고하지 않는다.
