기준: 사용자 승인 2026-11-01 최종 계획. 모바일 앱은 잠정 중단이며 이 작업 범위에서 제외한다. 운영은 전체 기능 검증 후 단일 전환한다.

## 현재 구현

- 공통 UI는 기존 FanAppHeader/BottomNavigation/SiteFooter/FanAction 재사용. `GroupsReleaseProvider`에 서버가 공개 boolean만 전달한다. 기본 off. on일 때 기존 HOME·커뮤니티·MY의 메뉴와 푸터까지 ‘모임’으로 전환한다.
- `/pages/groups`: 실제 `/api/groups` 데이터의 8개 카드, 팬·취미·브랜드/검색/정렬/가입·즐겨찾기 필터, 더 보기. 공개 카드와 본인 목록은 서버 데이터로만 표시한다.
- `/pages/groups/apply`: 실제 신청 저장. 결과는 개설 완료가 아닌 신청 접수. 재시도에도 같은 요청 키를 사용한다.
- `/pages/groups/[pageId]`: 실제 상세·가입 질문·가입·즐겨찾기·탈퇴·게시글 읽기/작성·회원 목록·비밀방 메시지·운영 설정/역할/소유권 이관/방 개설을 API와 연결했다.
- 기존 `/{slug}` 팬페이지: gate on에서 새 공통 정체성 헤더와 4탭, 기존 콘텐츠/팬 인증/이벤트/리더보드 하위 경로를 보존한다. Wave의 특수 행사 내비게이션도 보존한다.
- `/my/capsules`: 실제 지갑/캠페인/추첨/결과 조회. 고정 확률·재고 표시, 1회/10회 제한, 모든 회차 결과, owner별 요청 저장·재접속 복구를 구현했다. 응답 유실 후 새 키로 재차감하지 않는다.
- 디자인의 승인된 capsule-machine/open PNG를 `public/images/groups`로 복사했다. 생성·원본 변경은 없다.
- 서비스 UI 카피는 지원 12개 언어에 제공한다. 흰 기본 표면·핑크 활성·1px 경계·모바일 44px 컨트롤을 사용한다.

## 아직 전체 구현 완료로 볼 수 없는 부분

- 일반 모임 행사·신청·QR 티켓·현장 확인·후기·미션 제출과 검토·컬렉션을 실제 API에 연결했다. 관리자는 revision을 포함해 편집하며, 행사/미션/컬렉션 목록과 검토 목록을 다음 커서로 이어 읽는다. QR 생성 실패는 오류와 재시도로 처리한다.
- 관리 화면의 생성 폼은 접힌 섹션으로 분리했다. 비밀방 상태/예약 변경과 회원 역할/소유권 이관도 실제 API에 연결했다.
- 일반 추첨은 실제 티켓 차감·같은 요청 복구·수령 정보·전달 완료/취소 API를 사용한다. 활성 동의문이 없는 경우 수령 폼을 열지 않는다. 승인된 한국어/영어 동의문 원문과 각 필수 항목을 표시한다.
- 기존 canonical 팬 게시판은 기존 FanPostFeed/API를 유지한다. 기존 글을 일반 group_posts로 복사하지 않았다. 새 가입자 권한은 코어 작업자의 서버 통합 검증 대상이다.
- 전체 200보드와 실제 상태 대응, 모든 언어·폭·권한 시각 검수, DB 이관·운영 배포는 주 작업자가 통합 검증한다. 이전 Pen 100점을 구현 점수로 재사용하지 않는다.

## 목록 이동의 구현 결정
원본 일부 화면의 번호 페이지는 기존 서버의 cursor 기반 `더 보기`로 구현한다. 정렬·검색 조건을 유지한 채 다음 결과를 추가하며, 새 조건에서는 이전 목록·cursor를 초기화한다. 페이지 번호와 임의 offset을 새로 만들지 않아 중간 삽입으로 인한 중복·누락 위험을 줄인다. 시안의 번호 모양까지 동일하게 구현했다고 주장하지 않는다. 요청한 목록 수량과 각 행의 정렬은 실제 카드·상태 검증 기준을 그대로 따른다.
