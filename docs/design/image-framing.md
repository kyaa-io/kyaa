# 이미지 표시와 검수 기준

모든 이미지 신설·교체·UI 수정에 적용한다. 이 문서는 현재 `DESIGN.md`의 이미지 계약을 구체화한다. 사용자 승인 구도와 이미지 역할을 우선하며, 아래 기준을 확인하지 않은 화면은 완료로 보고하지 않는다.

## 공통 원칙

- 원본과 브라우저 표시 결과를 따로 확인한다. 원본 비율·해상도·내장 여백과 CSS의 고정 비율·최소 높이·정렬·크롭을 구분한다.
- 의도하지 않은 상하·좌우 빈 띠, 글자·로고·얼굴·단체 구성원의 부적절한 잘림, 가로세로 왜곡, 깨진 이미지와 과도한 저해상도 확대를 불합격으로 처리한다.
- 빈 띠를 없애려고 전역 `cover`, 과도한 확대, 흐린 복제 배경을 적용하지 않는다. 내용을 보존한 채 표시 틀을 원본 비율에 맞추거나 해당 슬롯에 맞는 원본을 사용한다.
- `contain`은 내용을 보존하는 방식이지 검수 통과의 근거가 아니다. 반대로 상품 배경·로고 안전 영역·여권 장식의 의도된 여백을 결함으로 일괄 제거하지 않는다. 예외는 역할·소유 컴포넌트·이유와 실제 캡처로 설명한다.
- 이미지 교체는 원본을 보존하며 기존 자산과 맞지 않는 이전 크롭·확대 값을 승계하지 않는다. 등록 사진의 `cover`는 해당 자산 리비전에 승인된 프레임만 사용한다.

## 역할별 소유자와 표시 방식

- 외부 영상 썸네일은 `MediaThumbnail`이 소유한다. 가로 영상은 16:9, 세로 영상은 원본 비율을 유지하고 제목·출처를 옆에 배치한다. 세로 표지의 얼굴·내장 문구를 가로 틀로 잘라내지 않는다. 원본 부재·로드 실패 시에는 동일한 16:9 출처·유형 표시를 사용하며 원본 링크를 유지한다.

| 역할 | 공통 소유자 | 적용 기준 |
| --- | --- | --- |
| 글자·로고가 포함된 브랜드 배너 | `CreatorHeroPicture` + fanpage의 brand hero | 자연 비율과 내용에 맞는 높이. 필수 문구와 로고를 모두 보존한다. |
| 홈 배너 | `ManagedHomeBanner`, `HomeHeroBanner`, `LiveHeroCarousel` | 모바일·데스크톱 원본과 캐러셀 틀을 각각 검사한다. 모바일 대체 원본과 768px 경계도 확인한다. 고정 슬롯에 맞지 않는 원본을 빈 띠로 통과시키지 않는다. 모바일 크리에이터 환영·GGGI 배너는 원본 비율의 사진 아래 흰 바탕에 설명과 버튼을 배치한다. 캐러셀은 가장 긴 슬라이드에 높이를 맞춰 자동 전환 때 높이가 바뀌지 않게 한다. |
| 인물·단체 사진 | `CreatorImage`, `CreatorPortrait`, `CreatorAvatar`, `CreatorHeroPicture` | 정사각형·원형·세로·배너 크롭을 구분한다. 얼굴, 그룹 구성원, 승인 초점을 보존한다. 호출 화면에서 별도 확대·초점을 복제하지 않는다. |
| LIVE 사진·포스터 | `EventPhoto` | 상세와 모바일 크리에이터 LIVE 목록의 전체 사진은 원본 비율을 따른다. 승인된 크롭과 미리보기 영상의 프레임은 보존한다. 목록·최근 활동·참여 안내는 각 슬롯에서 별도 검사하며 상세 변경을 무조건 전파하지 않는다. |
| 게시물·공지·외부 미디어 | `ContentAssetImage`, `NoticeBody`, 게시물/미디어 소유자 | 카드 미리보기와 원문 보기를 구분한다. 원문에서 전체 내용을 읽을 수 있어야 한다. 비공개 파일의 인증·blob 수명·오류 처리를 보존한다. |
| 상품·래플 | `BenefitArtwork`, `RaffleArtwork`, 결과 화면 | 상품 전체와 고유 로고를 확인한다. 비피오 합성 구도·스태츄의 상품 배경처럼 의도된 구성은 별도 예외다. 자산 교체 후 같은 예외가 유효한지 다시 확인한다. |
| 패스포트·스탬프·달력 장식 | passport artwork, `CalendarArt` | 펼친 책, 그림자, 투명 영역, 스티커 겹침은 전체 구성으로 판단한다. 프로필 크롭 규칙을 장식에 적용하지 않는다. |
| 지도·행사 안내·정적 페이지 | connect/marketing/page 소유자 | 안내 글자와 지도 표식의 가독성을 보존한다. 장식 배경과 정보 이미지를 구분한다. |
| 인증 증빙·관리자 미리보기 | certification/admin 소유자 | 증빙은 전체 내용을 읽을 수 있어야 한다. 관리자 미리보기만으로 실제 공개 화면 검수를 대체하지 않는다. |

## 필수 검수 순서

1. 바뀌는 공통 컴포넌트의 모든 호출 화면과 이미지 역할을 먼저 적는다. 실제 공개 자산, 로그인 상태, 빈 상태, 실패 상태를 구분한다.
2. 이미지와 필요한 데이터를 로드한 뒤 **390px와 1440px**에서 확인한다. 반응형 원본/프레임이 바뀌면 **768px**도 확인한다. 긴 번역, 정사각형·세로·가로 원본, 모바일 대체 원본을 변경 영향에 맞춰 추가한다.
3. 자연 비율 화면은 이미지 표시 비율과 원본 비율, 사진과 틀의 크기, 가로 넘침을 측정한다. 승인 크롭은 얼굴·글자·로고가 실제로 남는지 눈으로 확인한다. 로드 전후 높이와 레이아웃 이동도 확인한다. 치수가 없는 기존 원본은 임시 비율에서 실제 비율로 바뀔 수 있으므로 그 한계를 기록한다.
4. 전체 화면의 구성과 해당 이미지의 실제 표시 크기를 직접 본다. 로딩 화면, 축소 썸네일만 본 결과, API 성공, jsdom 또는 토큰 검사만으로 시각 검수를 통과시키지 않는다.
5. 증거에 경로·폭·언어·상태·자산/슬롯·판정·캡처를 남긴다. 전체 사이트 점검은 위 역할별로 `pass`, `fail`, `access gap`을 기록한다. 비공개 자료·인증 부재·현재 콘텐츠 부재는 실제 확인 범위와 분리한다.
6. 회귀 가능한 역할 선택·리비전 승인·fallback·영상 분기 등은 기존 자동 검사에 넣고, 배치·크롭·원본 내 여백은 실제 브라우저 검수를 필수로 남긴다. 새 화면도 같은 기준을 적용한다.

## 저장소 검사 연결

- 진입 지침: 루트 `AGENTS.md` → `DESIGN.md` → 이 문서.
- 자동 계약: `apps/web/components/fan-ui/*test.tsx`, `apps/web/features/live/ui/live-event-screen.test.tsx`를 기존 `Fan design system` CI에서 실행한다. 지침과 `docs/design/**` 수정도 같은 CI를 실행한다.
- 시각 완료: 자동 검사와 별도로 위 검수 근거가 필요하다. 자동 통과는 빈 띠·안면 크롭·해상도에 대한 미적 통과를 뜻하지 않는다.
- 운영 UI를 바꾸면 새 배포 안내와 공개 가능한 실제 수정 후 캡처를 함께 남긴다. 기존 안내와 원본 자산을 덮어쓰지 않는다.
